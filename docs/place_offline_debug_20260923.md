## 2. 本次发现并修复的问题

| 问题 | 修复 |
|---|---|
| 新执行脚本传入 `--execute`，Python 参数解析器却不认识它 | 注册参数；用不启动 ROS 的测试验证调试/执行两个入口 |
| 单个物体六段预览正确，但第二个物体又从当前真实关节位置开始 | 批次预览维护上一物体退回后的虚拟关节状态；真实执行仍逐物体读新反馈规划 |
| 预览虚拟状态在批次结束后残留，污染后续独立规划 | 批次结束或异常时清除预览状态 |
| 计算了壁面法向但姿态固定为水平闭合轴 | 新放置配置启用 `wall_normal`；Y 轴为壁面外法向，Z 轴朝下沿壁面，X 轴补成右手系 |
| 原壁面邻域按距碗中心排序，可能选中底部或别侧点 | 改为抓取锚点下方、同侧 25 mm 水平半径和 30 mm 深度内的局部壁面 |
| 近似一条线的点也可能产生任意 PCA 法向 | 校验第二特征值、平面残差、方向和倾角；证据不足拒绝实例，不伪造倾角 |
| 局部高度带中位数可能落到较低的碗壁 | 抓取锚点取局部高度上半部分的中位数 |
| 一个异常实例的几何计算异常中断整批 | 按实例记录拒绝原因，其余有效实例继续，各保留一个 Pose |
| Rim 节点把采集时间改成当前时间 | 保留原采集时间，防止旧观测被重新标记为新批次 |
| 只检查批次过期，未检查未来时间；长时间规划后未再检查首次执行时效 | 复用完整时间校验，在首次真实运动前再次校验；后续按冻结批次执行 |
| readiness 未受外层取消/超时约束 | 使用有界调用；异常时设置取消事件 |
| 下游默认相信输入顺序 | 按基座 XY 距离稳定排序，保证从近到远 |
| 调试发布的是另一份保存的准备位姿，可能与 TF 转换后执行值不同 | 从实际规划使用的 approach/grasp/ready/drop 发布调试消息 |
| 日志缺少失败物体和完成数量 | 结果增加 object_index（零起始）、object_count、completed_count；执行状态带物体索引 |
| 调试程序收到任意一个六段预览就可能通过 | 要求预览数量与本批物体数量一致，并留出跨 Topic 消息到达时间 |
| RGB/深度允许相差 5 秒，掩码和深度可能错配 | 新放置配置改为 100 ms，队列 20；相机恢复后必须确认真实配对，不能沿用旧 5 秒结果作为严格同步证据 |

旧单目标配置默认 `orientation_mode=vertical` 保持竖直夹爪；新放置配置明确为 `wall_normal`。竖直平移路径没有变成沿工具轴插入。法向估计不可靠时拒绝该实例，不自动降级为猜测姿态。默认最大壁面倾角 40° 是可调的初始范围，现场有效范围仍需采样确认。

## 3. 执行流程与位姿约定

1. 一次 YOLO bowl 实例分割。掩码对应有组织深度点云；不同实例以 `object_id` 区分，重叠像素归属置信度较高的实例。
2. 点云按采集时刻转换到 `base_link`。逐实例生成唯一 `grasp_center` 位姿；XYZ/Pose 通过 `/rim_locator/grasp_poses`，RPY(rad) 和 object_id 对应关系通过 `/rim_locator/status`。
3. 按 `sqrt(x²+y²)` 升序锁定批次。没有多候选、评分选优、重新检测或抓取反馈恢复。
4. 每碗六段机械臂路径：接近 → 下降抓取 → 原地抬升 → 固定放置准备位 → 垂直下降 0.20 m → 放开后原路抬升到准备位。
5. 夹爪命令穿插为：到达接近位后 Open；到抓取位后 Close；到放置位并确认到位后静止 1.0 s，再 Open；然后抬升返回。
6. 所有竖直段沿 **base_link Z**，XY 和姿态保持不变。抓取抬升高度为 0.15 m；放置下降和返回高度为 0.20 m。
7. 固定参考使用配置中的 `base/tool0` 完整位姿，通过静态 TF 转成 `base_link/grasp_center`。不会读取当前位置作为新的放置目标。原有转换一致性审计保留；配置里保存的已转换 Pose 与转换结果不一致时拒绝，修改固定参考时需同步更新审计记录。
8. 首次执行前持久化认领整批；同一采集时间、同一批位姿不能因节点重启再次执行。发生明确失败就终止该批，不自动释放、重试或抓下一碗；状态记录失败步骤和已完成数量。

正式配置的参考转换结果约为 `XYZ=(0.3888297, 0.3898899, 0.2582636) m`，下降后 Z 约为 `0.0582636 m`。这表示夹持中心的坐标，不是重新测得的现场位置。接收容器需对应固定放置位置；本版不定位容器，移动容器不会自动改变放置目标。
